# Resume

- [master-resume.md](master-resume.md) — the **single master resume source of truth** (content + header/design notes).
- [resume-strategy.md](resume-strategy.md) — rules, ATS approach, and how role versions are derived.
- [ats-analysis.md](ats-analysis.md) — readiness methodology + per-role JD keyword analysis.
- **Mohammed_Shabaz_S_Master_Resume.pdf** / **.docx** — generated, ATS-friendly, one page, selectable text, clickable links (email, LinkedIn, GitHub, per-project repos).
- **Mohammed_Shabaz_S_Master_Resume.txt** — extracted plain text (what an ATS sees), written by the validator.
- `assets/` — header icons (LinkedIn, GitHub), generated by `scripts/make_icons.py`.

Research behind it: [../research/TIER1_RESUME_RESEARCH.md](../research/TIER1_RESUME_RESEARCH.md).

## Regenerate

```
python3 scripts/make_icons.py        # only if the icons are missing
python3 scripts/build_resume.py      # writes the PDF + DOCX from master-resume.md content
python3 scripts/validate_resume.py   # extracts PDF text, writes .txt, prints readiness breakdown
```

Facts here must always match `../PROFILE.md` and the canonical files under `../profile`, `../experience`, `../projects`, `../skills`, `../certifications`. Edit content in `build_resume.py` + `master-resume.md` together, then rebuild and re-validate.
