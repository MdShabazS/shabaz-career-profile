## Technical Q&A for these companies
- **Q: Java: What are OOP pillars?**
  **A:** Encapsulation, inheritance, polymorphism and abstraction. Use a short example: a Vehicle base type, Car overriding behavior, private fields accessed through methods, and interfaces hiding implementation details.
- **Q: Java: abstract class vs interface?**
  **A:** An abstract class can have state and partially implemented behavior. An interface defines a contract; modern Java can also have default/static methods, but it is mainly used for capability-based design.
- **Q: Java: == vs equals?**
  **A:** == compares references for objects; equals compares logical content if implemented. For strings, use equals for value comparison.
- **Q: Java: final keyword?**
  **A:** final variable cannot be reassigned, final method cannot be overridden, final class cannot be inherited.
- **Q: DSA: How do you choose data structure?**
  **A:** Start with operations: search, insert, delete, ordering and memory. Array for indexing, hash map for key lookup, stack/queue for order constraints, tree/heap for hierarchy or priority.
- **Q: DSA: Time complexity of binary search?**
  **A:** O(log n), but it requires sorted data.
- **Q: DSA: Stack use case?**
  **A:** Function call stack, undo operations, expression evaluation, valid parentheses.
- **Q: SQL: JOIN types?**
  **A:** INNER returns matching rows, LEFT returns all left rows with matches if present, RIGHT returns all right rows, FULL returns all rows from both sides where supported.
- **Q: SQL: WHERE vs HAVING?**
  **A:** WHERE filters rows before grouping; HAVING filters groups after GROUP BY.
- **Q: SQL: primary key vs foreign key?**
  **A:** Primary key uniquely identifies a row. Foreign key references a primary/unique key in another table to maintain relationship integrity.
- **Q: Testing: unit vs integration testing?**
  **A:** Unit testing checks a small function/class alone. Integration testing checks whether multiple modules work together correctly.
- **Q: Testing: severity vs priority?**
  **A:** Severity is technical/business impact of a defect. Priority is how soon it should be fixed.
- **Q: Testing: smoke vs sanity testing?**
  **A:** Smoke checks basic stability after a build. Sanity checks a focused change area after a small fix.
- **Q: SDLC: Agile vs waterfall?**
  **A:** Waterfall is sequential; Agile is iterative with feedback in short cycles.
- **Q: REST: GET vs POST?**
  **A:** GET retrieves data and should be safe/idempotent. POST submits data and may create/change resources.
- **Q: Git: merge vs rebase?**
  **A:** Merge preserves branch history with a merge commit. Rebase rewrites commits onto a new base for linear history.
- **Q: Android: Activity lifecycle?**
  **A:** Core callbacks include onCreate, onStart, onResume, onPause, onStop and onDestroy. Mention saving state and releasing resources.
- **Q: Android: Why avoid work on main thread?**
  **A:** The main thread handles UI. Long work there freezes the app and can cause ANR; use background threads/coroutines.
- **Q: AI/ML: training vs inference?**
  **A:** Training learns model parameters from data. Inference uses the trained model to make predictions on new input.
- **Q: AI/ML: accuracy vs precision?**
  **A:** Accuracy is overall correct predictions. Precision measures how many predicted positives were actually positive.
- **Q: Computer vision: why preprocessing?**
  **A:** It improves consistency by resizing, normalizing, reducing noise or converting color spaces before model input.
- **Q: Embedded: polling vs interrupt?**
  **A:** Polling repeatedly checks a condition. Interrupts react when an event occurs, improving responsiveness.
- **Q: Embedded: why non-blocking millis logic?**
  **A:** It lets multiple tasks continue without freezing the loop, unlike delay-based code.
- **Q: Embedded: debouncing?**
  **A:** Mechanical switches can produce noisy transitions; debouncing filters those transitions in hardware or software.

- **Q: Automotive BCM: What is the state machine?**
